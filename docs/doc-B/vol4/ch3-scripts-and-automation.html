Scripts and Automation

The SEJA harness ships roughly 76 helper scripts. Most are shared utilities in .claude/skills/scripts/; some are skill-owned and co-located next to the SKILL.md that uses them (for example, generate_decision_digest.py lives in .claude/skills/post-skill/ and check_docs.py in .claude/skills/critique/); and a handful of private-only tools live under .claude/skills/scripts/priv/. This chapter documents the most important user-facing scripts and their command-line interfaces, explains how to run the validation suite, and shows how to extend it with a new check.

Every command-line interface below was verified against the actual script (its argparse setup and --help output). Where a script exposes subcommands, the subcommands are named explicitly.

Validation and Orchestration Scripts

These scripts run the harness's checks -- either as an orchestrated suite or as focused validators. They are invoked by /critique, by post-skill safety gates, and by the pre-commit hook.

run_all_checks.py

The CI-independent validation orchestrator. It discovers every check_*.py script (see Extending the Validation Suite), runs each in a subprocess, and rolls the results into a single pass/fail verdict with a per-check summary table. Exit codes: 0 = all pass, 1 = one or more failed, 2 = orchestrator error.

Flag Effect
--root ROOT Repository root directory (default: auto-detected)
--junit PATH Write a JUnit XML report to PATH (for CI pipelines)
--filter STACK Only run checks matching a stack keyword (e.g. flask, react), via check_plugin_registry.json
--verbose Stream child stdout/stderr to the console instead of capturing it

run_preflight_fast.py

The lighter-weight fast preflight gate. It runs a battery of quick checks (including call-graph freshness validation) suitable for git hooks and quick local validation. Post-skill step 6b runs it advisory; the pre-commit hook runs it as a hard gate.

Flag Effect
--ci Also run the framework unit tests (heavier; for CI use)
--verbose Show detailed output from each check

check_no_private_leaks.py

A private-only tool (.claude/skills/scripts/priv/check_no_private_leaks.py) that verifies no private content leaks to the public repository. It is the pre-commit leak gate and is also used before publishing. Exactly one of these mutually exclusive modes may be given:

Flag Effect
(no args) Scan authored prose in seja-public/ (docs/ and top-level *.md) for residual priv-only markers and known private-only patterns
--files PATH [PATH ...] Check specific source .md files pre-sync: apply the strip logic, then flag surviving fingerprints
--staged Check the staged .md subset (auto-discovered via git) -- the pre-commit gate
--candidate DIR Scan a publish-workspace candidate's .claude/ for leaked private content

check_docs.py

A plugin-based documentation consistency checker (.claude/skills/critique/check_docs.py) with six scanners: harness integrity, path liveness, env vars, command refs, terminology, and structural-completeness. Invoked by /critique.

Flag Effect
--root ROOT Repository root
--plugins PLUGINS Comma-separated plugin (scanner) names to run
--filter {error,warning,info} Minimum severity to report
--verbose Show extra detail

Index Generators

These scripts regenerate the derived indexes and reference artifacts that keep the workspace navigable. Most are run by post-skill step 7 after each skill invocation.

generate_macro_index.py

Regenerates the output directory's INDEX.md -- the unified artifact index listing every artifact with its metadata. Run at post-skill step 7b.

Flag Effect
--finalize ID Replace the RESERVED row for ID with the actual artifact metadata
--status {DONE,OPEN} Status to assign when finalizing (default: DONE)
--verbose, -v Show each file being processed

generate_briefs_index.py

Generates a lightweight briefs index for fast scanning, loaded by pre-skill budget-eval at the standard tier so the agent gets a compact summary rather than the full briefs file. Run at post-skill step 7a. The only flag is --verbose / -v (show each entry being processed).

generate_call_graph.py

A private-only tool (.claude/skills/scripts/priv/generate_call_graph.py) that statically parses SKILL.md, agent .md, and script files to build the harness call graph. It emits call-graph.json plus Mermaid and interactive Cytoscape.js viewers.

Flag Effect
--check Verify on-disk output matches the generator and all edges resolve; exit 1 on drift or unresolved references (wired into run_preflight_fast.py)
--strict In --check mode, also fail on suspicious references in the warnings list
--fixed-date FIXED_DATE Pin the generated timestamp (ISO8601) for deterministic output
--refresh-sri Fetch each CDN asset, compute its sha384 SRI hash, and rewrite the template's integrity= values (requires network)
--verbose Log every parsed edge, ref-load, and unresolved reference

generate_spo.py

A private-only tool (.claude/skills/scripts/priv/generate_spo.py) that generates the Structured Product Overview HTML from product-overview.yaml (project mode) or call-graph.json (harness mode). Invoked by /document --type spo.

Flag Effect
--project Project mode (default) -- render from product-overview.yaml
--harness Harness mode -- render from call-graph.json
--check Exit 0 if the output is fresh, 1 if stale
--drift Start with the drift overlay enabled (dims non-done cards)
--strip-internal Remove internal fields (owner, tracker, req/decision/journey IDs) from embedded JSON for external sharing
--output PATH Override the output file path

generate_decision_digest.py

A post-skill-owned script (.claude/skills/post-skill/generate_decision_digest.py) that generates a machine-readable decision digest (_output/decision-digest.jsonl) from D-NNN entries and advisory HIGH/MEDIUM recommendations. Invoked conditionally at post-skill step 7d. The only flag is --verbose / -v (show each entry being processed).

Markers, State, and Ledger Scripts

These scripts manage the harness's persistent state: lifecycle markers on Human (markers) files, the pending-actions ledger, the conversation trace, artifact IDs, and brief text handed between pre-skill and post-skill.

apply_marker.py

The sole write path for Human (markers) files. The agent may write only lifecycle markers to these files -- never prose -- and this script applies them. Required flags: --file, --id, and --marker.

Flag Effect
--file FILE Target file (repo-relative). Required.
--id ENTRY_ID Entry id, e.g. R-P-001. Required.
--marker {CHANGELOG_APPEND,DECISION_APPEND,ESTABLISHED,INCORPORATED,REQ_TRACED_BY,STATUS} Marker kind. Required.
--value VALUE Marker value (e.g. implemented or added). Required for STATUS and CHANGELOG_APPEND; ignored by the stamp-kind ESTABLISHED / INCORPORATED
--plan PLAN Plan id (accepts plan-NNNNNN or a bare 6-digit id)
--date DATE, --note NOTE Override date (YYYY-MM-DD); CHANGELOG note text
--dry-run Print the diff without writing

pending.py

The pending-actions ledger CLI, backing the /pending skill and pre-skill's pending-check stage. It is subcommand-based:

Subcommand Purpose
add Add a new pending action
done Mark an action as done
snooze Snooze an action until a date
dismiss Dismiss an action
list / due List all actions, or only those that are due
cleanup Auto-dismiss aged items
periodic-check Create periodic entries
status Composite status view (used by pre-skill; supports --overdue-days and --format banner)

conversation_trace.py

Manages the conversation trace log (_output/conversation-trace.jsonl) that records non-skill user-agent exchanges. Subcommands:

Subcommand Purpose
append Append a new utterance entry (--session-id, --emitter, --message, --type, --preceding-evt-id, optional --topic-tags, --confirm). Exit 2 signals masking was applied
backfill-skill Set led_to_skill on an existing entry (called by pre-skill brief-log)
last-evt-id Print the last evt_id for a session

reserve_id.py

Reserves the next artifact ID in INDEX.md, writing a RESERVED row that generate_macro_index.py --finalize later fills in. Required flags: --type (artifact type, e.g. research, plan) and --title. Optional: --dry-run (print the next ID without writing) and --output-dir (override OUTPUT_DIR).

brief_state.py

Persists and retrieves brief text between the pre-skill and post-skill phases, so the brief the user gave a skill survives across the two lifecycle hooks. Two subcommands: save (save brief text to the state file) and load (load the brief text and delete the state file).

The Configuration Module

project_config.py

Not a command-line tool but a library module imported by nearly every other script. It parses product-design/conventions.md (falling back to template/conventions.md when the project file is absent) and exposes project-specific paths and settings through a small API: 

from project_config import REPO_ROOT, get, get_path, get_list

backend_dir = get_path("BACKEND_DIR")
subpackages = get_list("BACKEND_SUBPACKAGES", ["api", "models", "services"])

REPO_ROOT is the auto-detected repository root; get / get_path / get_list read scalar, path, and list-valued conventions respectively, each accepting a default. Centralizing convention parsing here means a single change to conventions.md reconfigures every script at once -- the scripts never hard-code project paths.

Tip: Because project_config.py is a shared import, a new check script gains project-aware paths for free simply by importing from it -- no per-script configuration is needed. This is what makes the discovery convention in the next section low-friction.

Running the Check Suite

The harness offers two entry points for validation: the full orchestrator (run_all_checks.py) and the fast preflight gate (run_preflight_fast.py). Both are CI-independent -- they run identically on a developer's machine and in a CI pipeline.

Run every check with the orchestrator

From the repository root, run the orchestrator. It discovers and runs every check, prints a per-check summary table, and exits 0 only if all checks pass: 

# Run all checks from the repo root
python .claude/skills/scripts/run_all_checks.py --root .

For CI pipelines, add --junit to emit a JUnit XML report your CI system can parse, and --filter to run only the checks relevant to your stack: 

# Emit a JUnit XML report for CI
python .claude/skills/scripts/run_all_checks.py --root . --junit results.xml

# Only run checks tagged for the flask backend
python .claude/skills/scripts/run_all_checks.py --root . --filter flask

# Stream each check's output instead of capturing it
python .claude/skills/scripts/run_all_checks.py --root . --verbose

Run the fast preflight gate

For a quick local check before committing (and for git hooks), use the fast preflight gate. It is a subset tuned for speed: 

# Fast preflight -- the git-hook / quick-local gate
python .claude/skills/scripts/run_preflight_fast.py

# Also run framework unit tests (heavier; for CI)
python .claude/skills/scripts/run_preflight_fast.py --ci

# Show detailed output from each check
python .claude/skills/scripts/run_preflight_fast.py --verbose

Use run_preflight_fast.py for the tight edit-commit loop and run_all_checks.py for full-coverage sweeps (release preparation, CI, or when you want the JUnit report). Both honour the same exit-code convention: 0 means clean.

Tip: You do not usually run these scripts by hand. run_preflight_fast.py is wired into post-skill step 6b and the pre-commit hook, and run_all_checks.py is invoked by /critique validate. Run them manually when you want to validate outside the lifecycle -- for example, while iterating on a check script itself.

Extending the Validation Suite

Adding a new check to the suite requires no registration step and no edit to the orchestrator. run_all_checks.py discovers checks by filename convention: any file named check_*.py in the scripts directory or in a co-located skill subdirectory is picked up automatically.

How discovery works

The orchestrator's discover_scripts() globs check_*.py in .claude/skills/scripts/, then extends that list by globbing check_*.py in every sibling skill directory (each .claude/skills/<name>/ except scripts itself). The combined set is deduplicated and sorted, then each script is run as a subprocess with PASS mapped to exit code 0 and any non-zero exit to FAIL.

Add a new check

To add a check, follow the convention:

  1. Create a file named check_<something>.py in .claude/skills/scripts/ (a shared check) or in the owning skill's directory (a skill-scoped check).
  2. Make it a self-contained, runnable script: read the paths it needs from project_config.py, do its validation, and sys.exit(0) on success or a non-zero code on failure. Print human-readable failure details to stdout/stderr -- the orchestrator surfaces them in the summary and the JUnit report.
  3. Keep it under the 120-second per-check timeout the orchestrator enforces; a check that times out is reported as ERROR (exit code 2 from the orchestrator).

That is all that is required for the check to run in run_all_checks.py. Registration in check_plugin_registry.json is optional -- it is only needed if you want the check to participate in --filter STACK matching. A registry entry declares the check's name, its stack (backend / frontend keywords, or any), scope, and whether it is critical: 

// check_plugin_registry.json entry
{
  "script": "check_my_new_rule.py",
  "name": "My New Rule",
  "stack": { "backend": ["flask"], "frontend": [] },
  "scope": "api",
  "critical": true
}

A check not present in the registry is included by default (it runs on every unfiltered invocation) and only skipped when a --filter keyword is given that its (absent) registry entry cannot match. A registered check matches the filter when the keyword appears in any of its stack values, or when its stack lists any.
