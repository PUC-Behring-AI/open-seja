What the structural view offers

The Practitioner Track answers "how do I use this?" This track answers a different question: how is it built, and what happens if I change it? It is for readers evaluating the harness as a system — deciding whether to adopt it, integrating it into an existing toolchain, or preparing to extend it.

SEJA is a governance layer assembled from a small number of part types: skills that own a lifecycle phase, subagents that do bounded work in isolated contexts, reference files that carry shared knowledge, path-scoped rules that surface the right questions at the right moment, and scripts that enforce what prose cannot. The value of reading it structurally is that these parts constrain each other. Where a skill may write, when a hook fires, which reference a review must load — none of these is incidental, and changing one without seeing the others is how a governance layer quietly stops governing.

This track is a route, not a second copy of the documentation. Every phase below links into the shared core that all readers use; the only pages unique to this track are the four extension guides in Phase 2, which exist because no other audience needs them.

Phase 1: The Topology

Start with the shape of the system. Read the reference pages first to see what the parts are, then the concept pages to see why they are arranged this way.

  1. Call Graph — the whole system in one picture: which skills invoke which agents, load which references, and call which scripts. The fastest way to see the real shape rather than the intended one.
  2. Skill Map — how the lifecycle skills relate to one another and where each sits on the canonical path.
  3. Pipeline Stages — the stages every skill invocation passes through, and which of them a skill may opt out of.
  4. Agents Catalog — the subagent roster by role, and what each one is responsible for.
  5. The Lifecycle Pipeline — why every skill is wrapped by the same two hooks, and what that buys the system.
  6. Enforcement Layers — the four layers of governance in depth, from the immutable constitution down to the guardrail scripts.

Phase 2: Extension Points

Four things you can add to a SEJA harness, each with its own contract. These pages exist only in this track; read them once you can place a change on the topology from Phase 1.

  1. Writing a Skill — the frontmatter contract, the lifecycle bookends, the required sibling files, and where a skill's scripts live.
  2. Writing a Subagent — the prompt file shape, the evaluator and generator roles, the constitution-injection trust boundary, and how a wrapper dispatches to one.
  3. Adding a Review Perspective — the tier system, the two-stage loading protocol, and the three places a new perspective must be registered.
  4. Modifying Enforcement Rules — path-scoped rules, the check-script contract, the commit-time hook chain, and the constitutional limit on bypassing it.

Phase 3: Maintenance

What running a harness installation costs over time: keeping the gates green in automation, and moving an installation forward without losing project state.

  1. Quality Gates — the validation surface as an operator sees it, rather than as an author changes it.
  2. CI Integration — running the full check sweep in a pipeline.
  3. Upgrading SEJA — moving harness files forward while preserving project-specific configuration.
  4. Release — how a tagged release is cut and published.
