how-to operations

Overview

Two skills produce human-facing material from your project's design and implementation state. /communicate generates stakeholder material tailored to a specific audience segment. /onboard generates a ramp-up plan for a new team member, tailored to their role and expertise level. Both write date-versioned output folders and both support batch modes for producing a full set in a single pass.

Stakeholder material with /communicate

/communicate <audience> targets one of four audience segments, addressable by name or by tag:

  • EVL — Evaluators: CTO, tech lead, or engineering manager assessing adoption.
  • CLT — Clients: project commissioner, business owner, or funding partner of the product.
  • USR — End users: the person using the software built with the harness.
  • ACD — Academics: researcher in semiotic engineering, HCI, or AI-assisted development.

--format <md|html|both> selects the output format (default both). --all generates material for all four segments in parallel; --source <file> reformats an existing advisory or markdown file for the target audience, and --deep adds deep-dive sections. Output lands in a date-versioned folder — <COMMUNICATION_DIR>/<YYYY-MM-DD> — so material generated on the same UTC date shares one folder and different dates create a versioned history. Filenames follow communication-<id>-<audience-slug>.<ext>, and when a date folder holds more than one artifact an index.md is generated to link them.

Onboarding plans with /onboard

/onboard <role-family> <expertise-level> generates a ramp-up plan. There are three role families:

  • BLD — Builder: developer, DevOps, or infra engineer.
  • SHP — Shaper: product designer, product manager, UX researcher, or analyst.
  • GRD — Guardian: QA, security, tech lead, or engineering manager.

And three expertise levels: L1 Contributor (junior to mid, individual contributor), L2 Expert (senior, deep expertise, needs trade-off context), and L3 Leader (staff/principal/manager, strategic or people influence). Role families can be combined (e.g. builder+guardian) for hybrid profiles. As with /communicate, output lands in a date-versioned folder — <ONBOARDING_PLANS_DIR>/<YYYY-MM-DD> — with filenames like onboarding-<id>-<name-or-role-slug>.md.

The role × level matrix

The three role families and three levels form nine single-role combinations. --all generates all nine in parallel; --all-levels <role> generates the three levels of one role; --all-roles <level> generates the three roles at one level; and --batch <spec-list> generates an explicit semicolon-separated set of specs.
