how-to skills

What it does

/help shows what skills are available and explains what each one does, in three layers of progressive disclosure. Layer 1 — overview (no argument): lists all user-facing skills grouped by workflow category — Getting started, Design & plan, Understand the system, Quality & review, Communicate, and Housekeeping — each with a one-sentence summary. Layer 2 — skill detail (/help <skill>): loads that skill’s Quick Guide (What / Example / When to use / Next step), its Arguments table, its category, and its related skills from the skill graph.

Layer 3 — interactive browse (/help --browse): scans .claude/skills/, groups the discovered skills by metadata.category, shows category counts, renders a Mermaid skill-relationship diagram, and walks you through picking a category, then a skill, then executing it. Internal lifecycle hooks (pre-skill, post-skill) are excluded from the menus.

When to run it

Run /help when you want to know what the harness can do, need details about a specific skill before running it, or want to browse the full catalogue interactively and launch a skill from the menu. Start with bare /help for the workflow-grouped overview, /help <skill> when you already know which skill you want to inspect, and /help --browse to explore by category with the relationship graph.

/help is not for execution — it explains and navigates but does not perform the work itself. Once you know which skill to run, invoke it directly.

How it fits the lifecycle

/help is a navigation utility that sits off the main lifecycle spine rather than at a fixed stage on it. It is the way in to the canonical path — /research → /design | /plan → /implement → /critique → /document | /communicate → /reflect — rather than a step on it: it helps you discover and choose the right skill for the stage you are at.

Because it reads the same skill graph that connects the lifecycle skills to one another, /help <skill> and /help --browse surface which skills naturally follow the one you are looking at, making it a companion to every stage rather than the property of any single one.
