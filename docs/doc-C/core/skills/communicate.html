What it does

/communicate generates tailored communication material for a specific stakeholder audience segment. Each audience gets content in its own language, focused on what matters to it: evaluators (EVL — technical depth, architecture decisions, quality evidence), clients (CLT — value proposition, ROI, project outcomes), end users (USR — features, benefits, how-to guidance), and academics (ACD — research context, methodology, theoretical framing).

The material is produced by communication-generator agents, one per audience. By default it emits both Markdown and HTML (--format can restrict this to one), --deep adds expanded Deep-dive sections, and --source reformats an existing advisory or markdown file for the target audience. Passing --all generates material for all four audience segments in parallel.

When to run it

Run /communicate when you need to present the project to a specific audience — evaluators, clients, end users, or academics — and want material that speaks their language. If you omit the audience and do not pass --all, the skill presents an interactive menu to choose one.

/communicate is not for new team-member onboarding (use /onboard) or project documentation about the system itself (use /document). Same-date material shares one date folder, creating a versioned history of what was shared and when.

How it fits the lifecycle

On the canonical path — /research → /design | /plan → /implement → /critique → /document | /communicate → /reflect — /communicate sits in the delivery stage, sharing that stage with /document. You validate with /critique before communicating outward.

The two delivery skills split by audience: /document produces reference material about the system, while /communicate produces stakeholder-facing material. A common follow-up is /onboard when someone also needs to be brought onto the project.
