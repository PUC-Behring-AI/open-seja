What it does

/onboard generates a personalised onboarding plan for a new team member — what to learn, in what order, and where to find things — based on their role family and expertise level. Three role families are supported: Builder (BLD — engineers, DevOps, infra), Shaper (SHP — product designers, PMs, UX researchers, analysts), and Guardian (GRD — QA, security, tech leads, engineering managers). Role families may be combined. Three expertise levels tailor the depth: L1 Contributor (new to the role or project), L2 Expert (experienced practitioner needing trade-off context), and L3 Leader (technical leader or architect).

Output is written to a date-stamped folder under _output/onboarding-plans/ in Markdown, HTML, or both (the --format flag; default is both). Batch flags — --all (all nine role×level combinations), --all-levels <role>, --all-roles <level>, and --batch — generate multiple plans in parallel. An optional --area focuses the plan on a domain such as backend, frontend, or auth.

When to run it

Run /onboard when a new team member is joining and you want a structured, role-appropriate onboarding experience rather than ad-hoc knowledge transfer. It is equally useful when you are the newcomer and want a clear learning path into the project and the toolkit.

It is not for stakeholder updates (use /communicate) or API and architecture documentation (use /document). If arguments are missing and you are not in batch mode, the skill asks for the role family and expertise level interactively.

How it fits the lifecycle

/onboard sits on the communication side of the canonical path — /research → /design | /plan → /implement → /critique → /document | /communicate → /reflect. Where /communicate produces stakeholder updates and /document produces system reference, /onboard produces role-tailored ramp-up material for people entering the project.

It draws on the project’s as-coded design and conventions to ground the plan in the real system, so it is most useful once a project has taken shape. A natural companion is /communicate when you also need stakeholder material for the same audience.
