What it does

/critique is the unified quality gate — one skill for every “is it OK?” question. It runs one of ten modes, one at a time: validate (project validation scripts), review (structured code review against quality perspectives), smoke (runtime smoke tests against API endpoints or UI pages), preflight (combined validate + review as a pre-merge checkpoint), health (harness self-diagnosis across nine built-in checks), test-plan (a structured manual test plan from a brief or recent plans), docs (documentation consistency scanners), freshness (git ahead/behind check for configured repos), telemetry (usage analytics from telemetry data), and semiotic-inspection (a Semiotic Inspection Method evaluation of interface communicability).

The skill is the user-facing orchestrator; the heavy lifting is delegated to evaluator agents and check scripts. The global --depth <light|standard|deep> flag overrides review depth for the review and preflight modes.

When to run it

Run /critique before committing, after making changes, or whenever you want to verify code quality, project health, harness integrity, documentation consistency, git freshness, usage patterns, or interface communicability. Modes are mutually exclusive, and exactly one is required — if you invoke /critique with no mode, it asks which one to run.

Reach for preflight as the go/no-go checkpoint just before a merge, review for a targeted look at staged changes or a directory, health for harness diagnostics, and test-plan when you need structured QA scenarios to walk through by hand.

How it fits the lifecycle

On the canonical path — /research → /design | /plan → /implement → /critique → /document | /communicate → /reflect — /critique is the validation stage: you validate before you communicate. It typically follows /implement, confirming the change is sound before the work is documented or shared.

Depending on what a mode finds, the natural next step branches: /plan to fix findings, /critique review for a deeper pass, /pending for outstanding actions, or /reflect on a clean run. /critique and /pending are intentionally separate — /critique is heavy-budget and produces diagnostic reports, while /pending drives interactive ledger curation.
