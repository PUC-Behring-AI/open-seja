What it does

/research answers questions about the project — architecture, design decisions, trade-offs. The agent researches your codebase, analyzes the question from multiple perspectives, and gives you actionable recommendations at HIGH, MEDIUM, or LOW priority.

It runs in two modes. In the default research mode it produces a structured report with perspective analysis and a recommendations summary; if it detects design decisions in the Q&A, it offers a decision-extract proposal flow — create a structured D-NNN entry now, defer it to the pending ledger, or skip. Two to five topic tags are derived automatically, and follow-up Q&A continues within the same session. The --deep flag activates a structured expert council debate for high-stakes decisions. In inventory mode (--inventory <pattern>), it scans the codebase and produces a structured catalog of all elements matching a pattern, such as every API endpoint or every form component.

When to run it

Run /research when you need guidance on a design decision, want to understand trade-offs, or are unsure about the best approach. Use --inventory when you need an overview of what exists in the codebase, and --deep for high-stakes decisions that benefit from structured multi-perspective debate.

From iteration 2 onward, /research is the usual lifecycle entry point: you ask your question here, and depending on what surfaces you move into /design when intent needs to change or into /plan when intent is set and you need a build plan.

How it fits the lifecycle

The canonical path is /research → /design | /plan → /implement → /critique → /document | /communicate → /reflect. /research (alongside /explain) sits at the head of that path — the investigation step you run to understand what you are about to change.

From here you branch forward: /plan turns recommendations into an actionable build plan (pass the research ID so the plan records its source), /plan --roadmap builds a full product roadmap, and /design takes over when research surfaces that intent itself must change first. After an --inventory run, /explain gives a deeper explanation of any catalogued item.
