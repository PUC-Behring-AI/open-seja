What it does

/pending lists and addresses the outstanding human actions the harness is tracking for you. The ledger lives at _output/pending.jsonl and is append-only, so history is never lost. Invoked with no argument (or list), it groups every open item by type and prints each one with type-specific advice on how to resolve it — which skill to run, which file to open — then stops.

Six subcommands cover the full lifecycle: list (read-only listing with advice), address (a guided resolution workflow for marker-flip types), add, done, snooze, and dismiss. Action types the harness files include implement, mark-implemented, test-implementation, verify-as-coded, update-documentation, apply-promote-markers, spec-drift-check, periodic-curation, incorporate-research-markers, create-decision-entry, and user-defined. All state transitions flow through pending.py; the skill never writes to the ledger directly, and marker flips on Human (markers) files always go through apply_marker.py.

When to run it

Run /pending after /implement if you chose to defer work for later review at post-skill, when pre-skill tells you there are pending actions, when the periodic curation trigger has fired, or any time you want to review what the harness is tracking for you.

Use /pending address <id> for a guided resolution of marker-flip types (it walks you through per-candidate confirmations), and /pending add, done, snooze, or dismiss to manage individual items. Pre-skill surfaces open items at the top of every skill invocation until they are resolved.

How it fits the lifecycle

/pending is a supporting skill that sits off the main lifecycle spine rather than at a fixed stage on it. The canonical path — /research → /design | /plan → /implement → /critique → /document | /communicate → /reflect — files pending actions at many points, and /pending is where you close the loop on them.

/pending and /critique are intentionally separate: /critique health merely reports the pending-ledger count as a diagnostic, while every mutation of the ledger flows through /pending. Common follow-ups from a curated ledger are /explain drift --promote after addressing periodic-curation items and /implement once outstanding review items are cleared.
