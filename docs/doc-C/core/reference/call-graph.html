Overview

The SEJA harness is a directed graph of components that reference and invoke one another. A static analyzer walks every SKILL.md, agent prompt, and helper script to discover the typed nodes (skills, agents, scripts, rules, and the three reference families) and the typed edges between them. The snapshot summarized here contains 224 nodes and 496 edges.

This page is a self-contained summary: the counts below were aggregated directly from the topology data and hand-written into the static tables. There is no runtime fetch and no live viewer — for the interactive skill-relationship view, see the Skill Map sibling.

Node types

Every node carries one of seven types. The three reference families — general, template, and project — are the shared knowledge base; skills, agents, and scripts are the executable surface; rules are the path-scoped auto-loaded guidance files.

The seven node classes and their counts (224 nodes total).
Node type Count What it is
script 82 Helper scripts (validation checks, index generators, converters) invoked by skills and hooks.
ref-template 50 Template references used by /design to generate project-specific files.
ref-general 46 Agent-agnostic shared references (conventions, perspectives, skill graph, standards).
skill 17 Skills — 15 user-facing plus the two internal lifecycle hooks (pre-skill, post-skill).
agent 16 Subagent prompts — 9 evaluators and 7 generators, invoked by thin-skill wrappers.
rule 7 Path-scoped rule files auto-loaded when Claude edits matching files.
ref-project 6 Project-specific references generated per project by /design.

Edge types

Every edge carries one of ten relationship types. Some describe control flow (a skill invokes a script, delegates to an agent, or orchestrates a lifecycle hook); others describe reference loading (eager-load, lazy-load, auto-loads, dynamic-load, reads) or module structure (imports); suggests captures the next-step skill-graph affordances.

The ten edge types and their counts (496 edges total).
Edge type Count Meaning
reads 121 A component reads a reference or data file at run time.
dynamic-load 102 A reference or file loaded on demand during execution.
imports 70 A script imports another Python module.
invokes 66 A skill or hook invokes a helper script.
lazy-load 38 A demand-pull reference listed for on-demand injection.
suggests 33 A next-step skill affordance drawn from the skill graph.
delegates 18 A skill delegates work to a subagent.
auto-loads 17 A path-scoped rule auto-loads when matching files are edited.
orchestrates 17 A skill orchestrates a lifecycle hook (pre-skill / post-skill).

Lifecycle path and delegation patterns

Reading the graph along the lifecycle path shows a consistent shape. The canonical path runs /research (or /explain) → /design | /plan → /implement → /critique → /document | /communicate → /reflect. Most user-facing skills orchestrate the two internal hooks — /pre-skill at entry and /post-skill at exit — which is why the orchestrates edges (17) cluster on those two hook nodes. The hooks in turn invoke the largest fan-out of scripts: /post-skill alone drives ten script invocations (brief marking, index regeneration, decision digest, preflight, commit-scope verification, telemetry), the single densest node in the control-flow layer.

Delegation follows a clean split between evaluator and generator agents. /critique is the heaviest delegator — it hands off to seven evaluator agents (code-reviewer, harness-health-evaluator, migration-validator, semiotic-inspector, standards-checker, test-plan-generator, test-runner) — while generator skills such as /document, /communicate, /onboard, and /explain each delegate to a single matching generator agent. /research delegates to the council-debate and research-reviewer evaluators. This is why the 18 delegates edges concentrate on a handful of orchestrating skills rather than spreading evenly.

The reference layer dominates by volume. Combined, reads (121), dynamic-load (102), lazy-load (38), auto-loads (17), and eager-load (14) account for the majority of all edges — reflecting that most of the harness's connectivity is knowledge wiring (which reference a component consults) rather than direct control flow. The imports edges (70) capture the Python module graph beneath the scripts, and suggests (33) encodes the next-step affordances that let one completed skill point the user at the appropriate follow-up.
