Operational detail

A marker is a small structured HTML comment stamped next to an item of design intent. This page is the operational reference for the marker system: the marker kinds, the single tool allowed to write them, the state transitions that tool enforces, and the guardrails that verify no other hand touched the file.

Boundary. The sibling Sign System page covers the conceptual model — why markers exist and what they stand for. This page covers only the operational mechanics.

What each marker does

Markers come in a fixed set of kinds. Some are stamped before an entry's heading; two append a line to a dedicated section of the file.

STATUS
A state marker stamped immediately before an intent entry's ### <id> heading, recording where the item is in its lifecycle. Its line carries the state value, an optional plan id, and a date: <!-- STATUS: implemented | plan-000123 | 2026-07-15 -->. STATUS is the only marker that replaces an existing line rather than stacking a new one, so an item carries exactly one STATUS at a time.
ESTABLISHED
A stamp-kind marker recording that a decision is now established: <!-- ESTABLISHED: plan-000123 | 2026-07-15 -->. It requires a plan id and takes no value. Stamps insert before the heading and never replace an existing line.
CHANGELOG_APPEND
Appends a pipe-delimited line to the file's ## CHANGELOG section — date | entry-id | action | plan | note — where action is one of added, revised, revoked, or superseded. A note is required. It records a change to intent as an audit line rather than a stamp on a heading.

The same tool also supports the INCORPORATED stamp (a research finding folded into intent), DECISION_APPEND (append a new D-NNN decision entry with an auto-assigned id to the ## Decisions section), and REQ_TRACED_BY (annotate a requirement marker with the plan that traced it).

Writing markers with apply_marker.py

apply_marker.py is the sole write path for a Human (markers) file. An agent that needs to update a marker must go through it; a direct Edit or Write on the file is forbidden. The invocation names the target file, the entry id, the marker kind, and (for STATUS and the append kinds) a value:

Key apply_marker.py arguments.
Argument Role
--file The target file, repo-relative. Must be classified Human (markers), or the write is refused.
--id The entry id whose heading the marker attaches to (e.g. R-P-001).
--marker The marker kind (STATUS, ESTABLISHED, CHANGELOG_APPEND, …).
--value Required for STATUS, CHANGELOG_APPEND, DECISION_APPEND, and REQ_TRACED_BY; ignored by the stamp kinds.
--plan / --date / --note Plan id (accepts plan-NNNNNN, a bare 6-digit id, or manual), an override date, and the CHANGELOG note.
--dry-run Print a unified diff without writing.

The script validates before it writes: it resolves the file and refuses any path not on the Human (markers) allowlist, then checks the constructed marker line against an allowed regex for its kind. It exits 0 on success, 1 on a validation failure, and 2 on a runtime error.

Allowed STATUS transitions

STATUS is a small state machine. When a STATUS marker already precedes an entry, apply_marker.py allows the new value only if the current-to-new transition is permitted, and it replaces the existing line rather than stacking a second marker. The legacy uppercase IMPLEMENTED marker from pre-2.8.3 files is normalised to the lowercase implemented value for the transition check, so a promote flip can replace it in place. An illegal transition exits with a validation error and leaves the file untouched.

Guardrail scripts

Two guardrails keep the marker system honest at commit time. Because apply_marker.py refuses to write to any file not on the Human (markers) allowlist, it cannot be turned against an ordinary file. And because every marker line is validated against its regex and legal transition, a malformed or illegal marker never lands. The companion verifier check_human_markers_only.py then runs during the post-skill commit and rejects any hunk in a Human (markers) file that is not a marker change — catching a prose mutation that tried to slip in alongside a legitimate marker.
