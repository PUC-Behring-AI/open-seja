A semiotic model of authorship

SEJA is grounded in semiotic engineering: the harness treats a software project as a system of signs that carry the designer's meaning to users, and it takes care that AI-generated changes never quietly overwrite that meaning. The practical expression of this idea is a sign system over the project's files: each file is classified by who may author its content, and design intent is made traceable through explicit markers. This page describes that model.

Boundary. This page covers the semiotic model — the meaning behind the classifications and markers. The sibling Marker System page covers the operational mechanics: the marker syntax, the tooling that writes them, and the enforcement that keeps agents inside the rules.

Four file classifications

Every file in a SEJA project falls into one of four maintainer classifications. The classification is not decoration: it decides whether an agent may write prose to the file at all, or may touch only its markers, or must leave it entirely to the designer.

Human
Authored by the human designer. The constitution and conventions are the canonical examples: they encode the designer's non-negotiable commitments and the project's ground truth. Agents read these files constantly but do not rewrite them.
Human (markers)
The prose is human-authored, but the file also carries machine-managed markers that track the lifecycle of individual items. The design-intent and UX-research files are the primary examples. Agents may write only the markers — and only through apply_marker.py, never with a direct Edit or Write. A verifier rejects any non-marker change during the post-skill commit.
Agent
Generated and maintained by the harness: plans, research logs, reflections, indexes, and the as-coded implementation record. These are written by post-skill or designated skill steps and are never hand-edited by the designer, so the machine-readable record cannot silently diverge from the harness's validation scripts.
Human / Agent
Shared authorship: either party may write prose. The engineering and design standards files are examples — a designer sets a standard and an agent may later extend it, with no marker gate in between.

The dividing line that matters most runs between design intent (human-authored, in Human and Human (markers) files) and implementation state (agent-maintained, in Agent files). The sign system exists to keep that line legible: an agent that wants to record progress against a piece of design intent may set a marker on the intent file, but it may not rewrite the intent itself.

Traceability markers

A marker is a small, structured HTML comment embedded next to an item of design intent — a section, a row, a requirement. It is a sign that stands for a lifecycle fact: “this intended item has been implemented,” “this decision is now established,” “this research finding was incorporated.” Markers give design intent stable, greppable IDs (for example the D-NNN decision namespace) so the harness can trace an idea from a research question through to the commit that realised it.

Because markers are the only channel through which an agent may touch a Human (markers) file, they are the hinge of the whole model. The agent writes only the STATUS, ESTABLISHED, INCORPORATED, DECISION_APPEND, and CHANGELOG_APPEND markers — and only after the designer confirms via an AskUserQuestion prompt. The prose around the marker stays human-authored. This is how the harness records that intent has been met without ever authoring the intent itself.

The epistemic stance

The sign system carries an epistemic stance as a preamble: SEJA must surface what is not yet known, not only what has been decided. Gaps, unverified assumptions, design debt, and open questions are made visible — in gap-flagged topology cards, heuristic-labelled coverage reports, and pending notices — rather than silently omitted (constitution principle Q2).

This is why classification and markers are not merely permission bookkeeping. A file left in the Human (markers) class with an unset marker is itself a sign: it says the intended item has not yet been implemented or established. The harness reads that absence and reports it, rather than papering over it. Governance (who may write) and epistemics (what is still unknown) are the two axes the sign system holds together: governance without epistemic support produces brittleness, epistemic support without governance produces drift (principle Q3).
