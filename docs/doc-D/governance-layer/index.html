Vol. 4: The Output and Governance Layer Phase 3

This volume is in draft status. All five chapters contain substantive content sourced from the harness codebase.

This volume covers everything that happens after execution: the artifacts SEJA produces, the enforcement mechanisms that keep outputs aligned with design intent, the scripts and automation that maintain harness health, drift detection and maintenance workflows, and the release pipeline for publishing. It is the operational maturity layer for teams that have moved beyond initial adoption.

Chapters

  1. 1. Output Artifacts Catalogs the 20 subdirectories under _output/, the 13 key files that anchor the harness workspace, and the artifact lifecycle from skill-execution creation through post-skill commit and INDEX.md registration.
  2. 2. Enforcement Architecture Documents SEJA's three-layer enforcement model -- post-skill advisory, pre-commit blocking, and CI coverage -- along with the Human (markers) classification, leak-prevention gate, path-scoped rules, and anti-patterns that undermine governance.
  3. 3. Scripts and Automation Reference for the 70+ Python scripts organized by function: validation, generation, marker management, index/metadata, sync, lifecycle support, design support, testing, and migration. Includes guidance on using run_all_checks.py and extending the validation suite.
  4. 4. Maintenance and Drift Covers freshness policies and periodic triggers (curation, spec-drift, git freshness), the /explain drift workflow for detecting and promoting design-implementation alignment, and the /seja-setup --upgrade migration path.
  5. 5. Release and Publishing End-to-end walkthrough of the /publish pipeline, tag conventions and version inference, the ephemeral publish workspace design, and the priv/public boundary that keeps design artifacts private while syncing harness files to the public repository.

Recommended Reading Order

Begin with "Output Artifacts" to understand what SEJA produces, then "Enforcement Architecture" to see how those outputs are validated. "Scripts and Automation" provides the technical details of the automation layer. "Maintenance and Drift" addresses long-term operational concerns. "Release and Publishing" is primarily relevant to SEJA maintainers and contributors.
