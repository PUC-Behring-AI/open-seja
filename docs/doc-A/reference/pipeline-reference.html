Pipeline Reference

Every user-facing skill invocation is bookended by two internal lifecycle hooks: pre-skill (6 composable stages that prepare context, load references, and enforce governance) and post-skill (a multi-step pipeline that updates design state, captures QA, regenerates indexes, and commits). Together they ensure that no skill runs without governance and no work is lost.

Pre-skill Pipeline

Pre-skill runs 6 stages in fixed order. Three are critical (always run, failure blocks the skill) and three are non-critical (error-isolated, skippable via metadata.skip_stages in the calling skill's SKILL.md frontmatter). Legacy stage IDs orphan-check and compaction-check are recognized as sub-steps of budget-eval.

Stage ID Critical Purpose Skip Conditions Failure Mode Sub-steps
1 help No Check if calling skill's arguments contain --help; if so, display SKILL-quickguide.md and stop N/A (runs first; if triggered, remaining stages are skipped entirely) Falls back to description field from SKILL.md frontmatter if quickguide not found Uses load_quickguide.py helper
2 brief-log Yes Insert a STARTED entry into the briefs file with UTC timestamp Never skipped Must succeed (file write required) Conversation trace linkage via conversation_trace.py backfill-skill
3 budget-eval Yes Parse calling skill's context_budget tier and load appropriate briefs Never skipped Warn on parse error Orphan detection (standard + heavy); Compaction warning (heavy only)
4 pending-check No Run pending.py status --overdue-days 14 --format banner Skipped if pending-check in calling skill's skip_stages Never blocks; informational only None
5 ref-load Yes Load reference files per context_budget tier Skipped for light tier Warn if skill has no metadata.references Mandatory refs; Mode 1 (eager-only) or Mode 2 (demand-pull)
6 constitution No Read and inject product-design/constitution.md Skipped for light tier; skipped if constitution in skip_stages Skip silently if file does not exist None

Stage 1: help

Before any other processing, check if the calling skill's arguments contain --help. If so:

  1. Read .claude/skills/<skill>/SKILL-quickguide.md and display its full body (YAML frontmatter stripped).
  2. If the sibling file does not exist, display the description field from the skill's SKILL.md YAML frontmatter.
  3. Stop -- do not proceed with the remaining pre-skill stages or the calling skill's instructions.

The shared helper load_quickguide.py at .claude/skills/scripts/load_quickguide.py is the canonical loader for scripts; the agent replicates its behavior here.

Stage 2: brief-log

Obtains the current UTC time via date -u +"%Y-%m-%d %H:%M UTC" and inserts a new entry as the first entry after the # Briefs Log header in the briefs file (newest entries first).

Format
STARTED | <datetime UTC> | <skill-name> | <brief>
Example
STARTED | 2026-03-19 21:00 UTC | plan | Add user profile page
Error briefs
Summarized to one sentence, prepended with ERROR:

Sub-step: Conversation trace linkage

After the brief-log entry is saved, calls conversation_trace.py last-evt-id and then conversation_trace.py backfill-skill to link the preceding conversation exchange to this skill invocation. Skips silently if no trace entries exist or the script is not found.

Stage 3: budget-eval

Reads the calling skill's SKILL.md and parses metadata.context_budget (default: standard). Acts per tier:

Tier Briefs Loading Then
light Skips all briefs and reference files (brief-log only) Skip ref-load and constitution stages
standard (default) Briefs index (briefs-index.md; generated via generate_briefs_index.py if missing) Proceed to orphan detection, then ref-load
heavy Full briefs file with recency windowing (first 50 entries, summary for older); also loads plan index Proceed to orphan detection and compaction warning, then ref-load

Sub-step: Orphan detection

Applies to standard and heavy tiers. Skip if orphan-check is in the calling skill's skip_stages. Scans for STARTED entries with no matching DONE. Lists the 5 most recent orphaned entries if found.

Sub-step: Compaction warning

Applies to heavy tier only. Skip if compaction-check is in skip_stages. Counts STARTED entries within the last 2 hours. If count exceeds 8, emits a warning suggesting a fresh conversation. Advisory only -- does not block.

Stage 4: pending-check

Runs pending.py status --overdue-days 14 --format banner. Prints the output verbatim if non-empty. Never blocks the skill invocation; purely informational.

Stage 5: ref-load

Applies to standard and heavy tiers only. Always includes three mandatory references:

  • product-design/conventions.md (falls back to .claude/references/template/conventions.md)
  • .claude/references/general/permissions.md
  • .claude/references/general/constraints.md

Mode 1: Eager-only (no eager_references field)

Reads and injects every file in metadata.references, resolving each path via the routing table (general/ maps to .claude/references/general/, template/ maps to .claude/references/template/). An empty references: [] is valid.

Mode 2: Demand-pull (eager_references field present)

  1. Eager tier -- reads and injects each file in eager_references alongside mandatory refs.
  2. Lazy tier -- entries in metadata.references not in eager_references become available on demand. Emits a compact numbered list with trigger hints.

An empty eager_references: [] is valid (all skill-specific refs lazy; only mandatory refs loaded upfront).

Stage 6: constitution

Reads and injects product-design/constitution.md. If the file does not exist, skips silently. Constitution is optional for backwards compatibility with projects that have not generated one yet.

Post-skill Pipeline

Post-skill runs after every skill invocation. It marks the brief done, aligns as-coded state, captures QA, verifies commit scope, regenerates indexes, and commits. Steps are numbered but do not run strictly in sequence -- some steps share a number prefix with sub-steps (e.g., 2, 2b, 2c, 2d, 2g) and step 7e runs between 7 and 8.

Step 0: Checkpoint Recovery

If ${OUTPUT_DIR}/.post-skill-checkpoint exists, reads it (format: <step> | <datetime> | <skill-id>). If <skill-id> matches the current invocation, resumes from the step after <step>. Otherwise deletes the stale file and proceeds normally.

Step order for resume: step 7e runs between 7 and 8, so a 7 token resumes at 7e (idempotent) and a 7e token resumes at step 8. When resuming from a 7 or 7e token, captures pre-commit-sha via git rev-parse HEAD.

Step 1: Brief-log DONE

Obtains UTC time and runs mark_brief_done.py --brief-pattern "<brief text>" --done-time "<datetime>" to mark the matching STARTED entry as DONE. Optionally includes --plan-id <id>.

Step 1b: Telemetry Prep

Prepares a telemetry record in context per the schema in SKILL-reference.md. Fields include skill name, id, outcome, timestamp, duration, token counts. The record is held in memory and flushed to disk at step 8b. The session_id is populated automatically from the CLAUDE_SESSION_ID environment variable.

Step 2: As-Coded Alignment

Runs only when the parent skill is /implement. Updates three sections of product-design/product-design-as-coded.md:

2a. Conceptual Design
Three branches: (1) File exists -- incremental anchor-based Edit on H3 subsections; (2) File absent, no legacy files -- instantiate from template; (3) File absent, legacy files present -- emit warning and skip. Appends a changelog entry to product-design-changelog.md.
2b sub-part. Metacommunication
Updates ### 4. Per-Feature Metacommunication Log with implemented intent. Uses first-person "I" (designer) and second-person "you" (user) phrasing. Tags changes source: agent (post-skill).
2c sub-part. Journey Maps
Skips if ## Journey Maps is a placeholder. Otherwise updates JM-TB-NNN statuses incrementally and the Delta from As-Intended section. Multi-section updates require multiple Edits (enforced by check_section_boundary_writes.py at step 6c).

Step 2e: DONE Marker Proposal

If the plan implemented user-facing features or journey steps, scans the as-intended/as-coded registry for items matching implemented features. Presents an AskUserQuestion with three options:

  • Apply now -- flip STATUS markers via apply_marker.py
  • Defer for later review -- add candidates to the pending ledger
  • Skip -- do nothing

Step 2f: Commit Scope Inclusion

Updated as-coded files and as-intended files with DONE markers are included in the commit scope at step 8.

Step 2b: Documentation Auto-run

Collects non-N/A Docs: fields from the plan. FEATURE/REDESIGN always trigger; FIX/CHORE trigger only when any step has non-N/A Docs:. If the parent carried --skip-docs, skips to step 2g pending action creation. Otherwise presents an AskUserQuestion:

  • Auto-run now (recommended) -- runs /document --plan <plan-id>
  • Skip -- files an update-documentation pending entry

Step 2c: Design Intent Curation Reminder

Informational only -- outputs a text reminder to consider promoting items to established status via /explain drift --promote. Does not perform the promotion itself. Highlights P0 priority sections.

Step 2d: Eager Implement Entry

Runs only when parent skill is /plan. Reads the plan header to extract the short title, then invokes pending.py add --if-absent --type implement --source plan-<id>. Silent on success; non-zero exit produces a warning. Uses --if-absent for idempotency under checkpoint recovery.

Step 3: QA Log

Three branches, evaluated in order:

Branch A: Skip
If the parent passed skip_qa_log: true. Currently used by /research (which embeds its own inline Q&A).
Branch B: Inline in plan file
If the artifact prefix is plan- or implement-, appends Q&A directly to the plan file under ## Q&A Log. Uses numbered ### Q<n> / ### A<n> exchange format. For subsequent implementations, inserts a separator comment and continues numbering.
Branch C: Companion file
For all other artifact types, runs /qa-log with no_commit: true. Filename follows <prefix><id>-qa-<slug>.md convention. Output directory resolved from prefix via the QA-Log Directory Mapping.

Step 4: Commit Message

Creates an appropriate commit message including the skill invocation id.

Step 5: Git-state Safety Check

Runs git status. Does NOT commit if:

  • A rebase is in progress (rebase-merge / rebase-apply in .git/)
  • An unmerged conflict exists
  • HEAD is detached

On main/master: warns and asks for confirmation. If blocked, outputs the commit message for manual use.

Step 6: Commit Scope Verification

Runs verify_commit_scope.py --skill-type <type> --artifact-id <id> to check staged files against expected paths. Passes --plan-id, --roadmap-id, and --always-include as applicable. The script outputs JSON with expected, staged, unexpected, missing, and pass keys. Unexpected pre-staged files trigger a warning.

Step 6b: Fast Preflight Gate

Runs run_preflight_fast.py. Exit 0 proceeds silently. Non-zero displays failures and asks whether to proceed or abort. Advisory, not blocking -- post-skill runs after lengthy work; .githooks/pre-commit is the hard gate. Script not found is silently skipped.

Step 6c: Human Markers Verifier

Runs check_human_markers_only.py --staged. Exit 0 proceeds silently. Exit 1 (prose mutation in a Human (markers) file) displays the violation and asks via AskUserQuestion whether to abort or proceed. Default recommendation: abort (unauthorized edit should go through apply_marker.py). Script not found is silently skipped.

Step 7: Index Regeneration

Four sub-steps:

7a. Briefs index
generate_briefs_index.py -- refreshes the briefs index file.
7b. Macro index
generate_macro_index.py -- refreshes the artifact index (INDEX.md).
7c. Cross-reference update
update_cross_refs.py --artifact <path> -- reads the source: header and updates the spawned: field on the source artifact.
7d. Decision digest regeneration (conditional)
If the completed skill was /research with HIGH/MEDIUM recommendations, or a plan applied DECISION_APPEND markers: runs generate_decision_digest.py to regenerate the decision digest JSONL file.

After sub-steps complete, writes a checkpoint and captures pre-commit-sha via git rev-parse HEAD.

Step 2g: Pending Action Creation

Runs when parent is /implement. Each sub-step is silent on success and emits a one-line warning on failure; never blocks.

2g.i. Verify-as-coded
If the plan's Modified + Created file count exceeds the verify-as-coded file threshold (default: 5 -- see Configuration Reference), files a verify-as-coded pending action.
2g.ii. Test-implementation
If the plan has a non-empty ## Test Plan, files a test-implementation pending action.
2g.iii. Update-documentation
If documentation auto-run was skipped (step 2b) and the plan has non-N/A Docs: fields, files an update-documentation pending action.
2g.iv. Implement mark-done safety net
Unconditionally runs pending.py done --source plan-<id> --type implement to close the entry filed at /plan step 7h. Idempotent.

Step 7e: Deferred-artifact Generation

Runs only when parent is /implement; skipped in --deferred worktree mode. Runs before the step 8 commit so the primary commit includes generated artifacts.

7e.a. Manual Actions
If any step requires manual operator action after deployment, maintains a ## Manual Actions section in the plan file with dev and production instructions separated. Idempotent: updates in place if section already exists.
7e.b. deploy.html
Scans the plan for steps with non-N/A Deploy: fields. If found, writes (create or overwrite) _output/docs/deploy.html with sections: Header, "Changed in plan-<id>" banner (visually highlighted), Docker, Standalone -- Linux, Standalone -- Windows, Change history. Synthesizes content from all prior deploy entries (from change history) plus current plan for full current deployment state.

Step 8: Commit

Stages all affected files (regenerated indexes, updated as-coded files, step 7e artifacts, plan file with Manual Actions) and commits using the message from step 4. Writes a checkpoint, then deletes it on success.

Step 8b: Telemetry Flush

Enriches the step 1b record with commit-dependent fields: git_commit_sha, files_changed, parent_skill. Runs build_telemetry.py to construct and append the record.

Gate: compares git rev-parse HEAD against the SHA captured before step 8. If equal (no primary commit), drops the telemetry record. Otherwise commits telemetry as a separate trailing commit: git commit -m "telemetry: <skill> <id>".

Steps 9--11: Wrap-up

Step 9: Surprises
Outputs surprises from execution with resolution status.
Step 10: Output link
Links to the generated file within the output directory.
Step 11: Completion
Outputs the SKILL COMPLETE banner with skill name and artifact id.

Step 12: Next-step Suggestions

Reads .claude/references/general/skill-graph.md and looks up the completed skill. Presents at most 3 suggestions plus an "End" option. Each suggestion carries the skill-graph reason and a "NOT recommended when" clause.

Suppression rules -- omit a suggestion when:

  1. Check modes ran at steps 6b or 6c -- omit /critique validate, /critique review, /critique preflight
  2. /document was offered or ran at step 2b -- omit /document
  3. The brief's plan prefix is CHORE or DOCUMENT -- omit /reflect

Worktree Deferred Mode

When --deferred is passed (by the roadmap parallel-wave orchestrator after merging a worktree branch back to main), post-skill runs a reduced pipeline. The orchestrator handles wave-level briefs, QA, and commits; --deferred handles only the per-plan state alignment that requires the merged code on main.

Step Normal Mode --deferred Mode Rationale
0 (checkpoint recovery) Run Run Recovery is always needed
1 (brief-log) Run Skip Orchestrator writes wave-level brief
1b (telemetry prep) Run Run Flushed at 8b
2 (as-coded alignment) Run Run Merged code is now on main
2b (documentation auto-run) Run Skip Orchestrator handles wave-level docs
2c (design intent reminder) Run Run Informational -- always useful
2d (eager implement entry) Run Skip Not from /plan
3 (QA log) Run Skip Orchestrator handles wave-level QA
4--6 (commit message, safety, scope) Run Skip Orchestrator commits atomically
6b--6c (preflight, markers check) Run Skip Orchestrator runs these once for the wave
7 (index regeneration) Run Run Indexes must reflect merged state
2g (pending action creation) Run Run Per-plan pending actions needed
7e (deferred-artifact generation) Run Skip Orchestrator handles wave-level docs
8 (commit) Run Skip Orchestrator commits
8b (telemetry flush) Run Run Appended; orchestrator includes in wave commit
9--12 (wrap-up, next-step) Run Skip Orchestrator handles wave-level completion

Checkpoint Recovery

Post-skill writes checkpoint files at critical points to enable crash recovery. The checkpoint file lives at ${OUTPUT_DIR}/.post-skill-checkpoint with format: 

<step> | <datetime UTC> | <skill-id>

Checkpoint locations in the pipeline:

Checkpoint Token Written After Resumes At
1 Step 1 (brief-log DONE) Step 1b (telemetry prep)
3 Step 3 (QA log) Step 4 (commit message)
7 Step 7 (index regeneration) Step 7e (deferred-artifact generation, idempotent)
7e Step 7e (deferred-artifact generation) Step 8 (commit)
8 Step 8 (commit) Step 8b (telemetry flush); checkpoint then deleted

When resuming from a 7 or 7e token, the pipeline captures pre-commit-sha via git rev-parse HEAD because step 8 has not yet run and HEAD is still the pre-commit state.
