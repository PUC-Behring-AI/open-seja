Skills Reference

Overview

SEJA provides 17 skills: 15 user-facing skills and 2 internal lifecycle hooks (pre-skill and post-skill). Each skill is defined in a SKILL.md file under .claude/skills/<name>/SKILL.md and follows the agentskills.io frontmatter spec with SEJA-specific extensions under the metadata key.

Skills are organized into four categories: utility (communication, documentation, onboarding, help, publishing, QA logging, pending actions, setup), analysis (critique, explain, reflect, research), planning (design, plan, implement), and internal (pre-skill, post-skill). Every user-facing skill ships a SKILL-quickguide.md sibling with a designer-friendly description and usage scenario.

For step-by-step usage guides, see Vol. 2: Skill-by-Skill How-To Guides. For the lifecycle pipeline that wraps every skill invocation, see Ch. 5: Pipeline Reference.

Context Budget Tiers

Each skill declares a context_budget in its YAML frontmatter under metadata.context_budget. Pre-skill uses this value to determine how much context to load into the agent's context window before the skill begins execution.

light
Skips all briefs and reference file loading. Only the brief-log stage runs (to record the invocation). Pre-skill skips the ref-load and constitution stages entirely. Used by skills that require minimal context: help, pending, publish, qa-log.
standard (default)
Loads the briefs index (${BRIEFS_INDEX_FILE} -- one-line summaries generated by generate_briefs_index.py) instead of the full briefs log. Proceeds to the orphan detection sub-step, then ref-load (mandatory references + skill-specific references) and constitution load. Used by most skills: communicate, design, document, explain, onboard, post-skill, pre-skill, reflect, research, seja-setup.
heavy
Loads the full briefs log (${BRIEFS_FILE}) with recency windowing: first 50 entries (newest first), with a summary for older entries. Also loads the plan index (${PLANS_DIR}/INDEX.md). Proceeds to orphan detection and compaction warning sub-steps, then ref-load and constitution. Used by context-intensive skills: critique, implement, plan.

Category Descriptions

utility
Skills that produce artifacts, manage project state, or provide information without requiring deep analysis. Includes communication generation, documentation, onboarding, help, publishing, QA logging, pending action management, and harness setup.
analysis
Skills that investigate, evaluate, or reflect on the codebase, design, or process. Includes critique (multi-mode quality evaluation), explain (behavior, code, data model, architecture, drift), reflect (on-demand reflection), and research (codebase Q&A).
planning
Skills that shape the project's future: defining design intent, creating implementation plans, and executing those plans. Includes design, plan, and implement.
internal
Lifecycle hooks not intended for direct user invocation. pre-skill runs before every user-facing skill (brief logging, budget evaluation, pending check, reference loading, constitution injection). post-skill runs after every user-facing skill (brief completion, as-coded alignment, QA logging, commit, telemetry, index regeneration, next-step suggestions).

Skip Stages Reference

Skills can declare skip_stages in their YAML frontmatter to opt out of non-critical pre-skill stages. Only non-critical stages may be skipped; the three critical stages (brief-log, budget-eval, ref-load) always run. Legacy stage IDs orphan-check and compaction-check are recognized as sub-steps of budget-eval.

Skill Skipped Stages Rationale
pending pending-check, orphan-check, compaction-check, constitution The pending skill itself manages the pending ledger; checking it at pre-skill would be circular. Constitution is unnecessary for ledger operations.
publish pending-check, orphan-check, compaction-check, constitution Publish runs its own validation pipeline; pre-skill checks would be redundant and add latency to the release workflow.
All other skills: no stages skipped (default behavior).

References Loaded per Skill

Each skill declares which reference files it needs in its metadata.references list. The loading mode depends on whether the skill also declares metadata.eager_references: Mode 1 (no eager_references field) loads every listed reference eagerly at pre-skill time; Mode 2 (field present) loads only the entries listed in eager_references eagerly and makes the rest available on demand (lazy / demand-pull). Mandatory references (conventions.md, permissions.md, constraints.md) are always loaded regardless of mode and are not repeated in the table below. SKILL.md Frontmatter Schema

Every SKILL.md file begins with a YAML frontmatter block following the agentskills.io specification with SEJA-specific extensions. For the complete file format specification, see Ch. 6: File Format Reference.

Field Type Required Description
name string Yes Skill name (1-64 chars, lowercase alphanumeric + hyphens).
description string Yes Human-readable description (1-1024 chars).
argument-hint string No CLI-style argument pattern shown in help output.
user-invocable boolean No Whether the skill can be invoked directly by users. Default: true. Set to false for internal hooks.
compatibility string No Runtime compatibility note (max 500 chars).
metadata.last-updated datetime No Last modification timestamp in UTC.
metadata.version semver No Skill version (semantic versioning).
metadata.category enum No One of: utility, analysis, planning, internal.
metadata.context_budget enum No One of: light, standard, heavy. Default: standard.
metadata.skip_stages list No Pre-skill stage IDs to skip. Only non-critical stages may be listed.
metadata.references list No Reference file paths loaded at pre-skill ref-load stage. Empty list is valid.
metadata.eager_references list No Subset of references loaded eagerly; remaining references become lazy (demand-pull). Presence of this field switches ref-load to Mode 2.
