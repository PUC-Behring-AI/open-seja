How to Onboard a Team Member

Goal: produce a personalized onboarding plan -- what to learn, in what order, and where to find things -- tailored to a role and experience level. The /onboard skill covers three role families and three expertise levels. Use it to onboard a new teammate, or yourself if you are new to the toolkit or the project.

When to Use

  • A new team member is joining and you want a structured, role-appropriate onboarding experience.
  • You are the newcomer and want a clear learning path into the project and the toolkit.
  • You want to generate plans for several roles or levels at once (batch modes).

Not for stakeholder updates (use /communicate) or API/architecture documentation (use /document).

Required Inputs

  • A role family and expertise level, e.g. /onboard shaper L2 Alice --area frontend.
  • Optionally a name and focus area.
  • For batch generation, a batch selector (--all, --all-levels <role>, --all-roles <level>, or --batch "<spec-list>").

Step by Step

  1. Choose a role family.
    Role familyAliasesFocus
    Builderbuilder, BLDEngineers -- code, architecture, testing
    Shapershaper, SHPDesigners, PMs -- product, UX, strategy
    Guardianguardian, GRDQA, security, ops -- quality, reliability
  2. Choose an expertise level. L1 (contributor / new to the role or project), L2 (expert / experienced practitioner), or L3 (leader / technical lead or architect).
  3. Decide single or batch.
    • Single plan -- Recommended when you are onboarding one specific person. NOT recommended when you want a library of plans for a whole team.
    • Batch (--all, --all-levels, --all-roles, --batch) -- Recommended when you want plans for several role-level combinations generated in parallel.
  4. Run the skill. Output artifacts carry the onboarding-NNN prefix and land in _output/onboarding-plans/. By default both Markdown and HTML are generated; restrict with --format md.
    Expected output: a role- and level-appropriate onboarding plan (for example a 30-60-90 day plan) tailored to the focus area.

Tip. Per-role learning paths, reading lists, and milestone checkpoints live in the onboarding reference files under .claude/references/general/onboarding/. Edit those files to change what each role learns.

Expected Outputs

  • One or more onboarding-<id>-* plans in _output/onboarding-plans/.
  • Markdown and/or HTML per the --format setting.
  • In batch mode, multiple plans generated in parallel (for example all nine role-level combinations with --all).

Common Mistakes

MistakeBetter approach
Using /onboard to produce stakeholder messaging. Audience messaging is /communicate; onboarding produces a personalized learning plan.
Onboarding at the wrong level. Match the level to the person: L1 for newcomers, L2 for experienced practitioners, L3 for leaders.
Omitting the focus area for a specialized role. Pass --area <focus-area> so the plan targets the right part of the codebase.
Hand-writing many similar plans one at a time. Use a batch selector (--all-roles, --all-levels, or --batch) to generate them in parallel.
