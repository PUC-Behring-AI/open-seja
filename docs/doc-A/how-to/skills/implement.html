How to Implement a Plan

Goal: carry out an approved plan, one step at a time, with a rollback branch and an end-of-run quality gate. The /implement skill runs a plan created by /plan. It has three execution modes: auto (default, each step in a fresh subagent), manual (--manual, sequential with per-step confirmation), and roadmap (--roadmap, all plans in a roadmap wave by wave).

When to Use

  • You have reviewed a plan and are ready to have the agent carry it out.
  • You want each step isolated in a fresh subagent to resist context degradation (auto mode, best for plans over six steps).
  • You want per-step confirmation on a small plan (use --manual).
  • You want to execute an entire roadmap wave by wave (use --roadmap <id>).

Required Inputs

  • A plan ID, e.g. /implement 000042. The ID must resolve via _output/INDEX.md.
  • For roadmap mode, a roadmap ID, e.g. /implement --roadmap 000316.
  • A clean working tree for the files the plan touches (the skill pauses if an affected file has uncommitted changes).

Step by Step

  1. Pick an execution mode.
    • Auto (default) -- Recommended for most plans, especially those with more than six steps where context degradation is a risk. NOT recommended when you need to confirm each step by hand.
    • Manual (--manual) -- Recommended for small plans (six steps or fewer) or when per-step confirmation adds value. NOT recommended for large plans where holding all context in one window degrades quality.
    • Roadmap (--roadmap <id>) -- Recommended when executing every plan in a roadmap without triggering each one. NOT recommended for a single standalone plan.
  2. Run the skill. It creates a rollback branch (pre-plan-<id>) before making changes, then executes.
    Expected output: per-iteration progress reports; a plan-<id>-progress.md file capturing cross-step learnings; commits per step.
  3. Let the quality gate run. Unless you pass --skip-checks, a Quality Gate runs at the end: validation, code review, tests, and smoke tests if the plan's smoke field is set. Auto mode adds a bounded generator-critic loop (max two retries) for critical review findings.
    Expected output: a pass/fail verdict; critical issues fixed or logged as unresolved.
  4. Handle documentation. For qualifying plans, post-skill offers automatic documentation generation. Pass --skip-docs to suppress the prompt (it files an update-documentation pending entry instead).

Tip. Auto mode follows a TDD red-green cycle for steps with an explicit Tests: field -- write the failing test first, then implement until it passes. Manual mode keeps test-after ordering because your presence is the quality checkpoint.

Expected Outputs

  • A rollback branch pre-plan-<id> (undo with git checkout pre-plan-<id>).
  • The plan file marked # DONE, with per-step checkboxes updated and an aggregated summary appended.
  • A Quality Gate report (unless --skip-checks).
  • In roadmap mode, per-wave rollback branches and each plan's roadmap Status flipped to done.

Common Mistakes

MistakeBetter approach
Implementing a plan you have not read. Review the plan with /plan first. /implement executes; it does not re-decide the approach.
Running auto mode on a plan with uncommitted changes in its files. Commit or stash first. The skill pauses on dirty affected files to protect your work.
Using --skip-checks routinely to "go faster". The Quality Gate is where correctness and security findings surface. Skip it only for a deliberate reason.
Forgetting the rollback branch exists after a bad run. Undo with git checkout pre-plan-<id> (or pre-roadmap-<id> / pre-wave-<N>-<id> in roadmap mode).
