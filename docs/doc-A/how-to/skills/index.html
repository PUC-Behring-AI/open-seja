Ch. 2: Skill-by-Skill Guides

SEJA exposes 15 user-facing skills (plus two internal lifecycle hooks, pre-skill and post-skill, which run automatically around every user-facing invocation and are not called directly). Each user-facing skill has its own goal-first guide in this chapter. This index groups those guides by the phase of the development lifecycle they serve, so you can find the right skill by asking "where am I in the work?" rather than memorizing skill names.

The Canonical Lifecycle

SEJA organizes work into a repeatable path. You begin by understanding what you are about to change, then shape intent (change the design, or plan within the existing design), build the change, validate it, share the results, and reflect on what you learned. The canonical path is:

The path is a default, not a cage. On the first iteration of a project, /seja-setup <target> hands off to /design to configure the project; from iteration 2 onward you start with /research (or /explain) to investigate what you are about to change, then branch into /design when intent needs to change or into /plan when it does not. The cross-cutting skills below support the path from the side rather than sitting on it.

Skill Guides by Phase

Understand

  • /research -- Answer questions about the codebase, architecture, or design decisions, logging Q&A pairs; with --inventory, catalog codebase elements matching a pattern.
  • /explain -- Explain behavior, code, data model, architecture, or spec drift with visual diagrams and analogies.

Shape Intent

  • /design -- Define or update project design: stack, conventions, domain model, conceptual design, and standards.
  • /plan -- Make a plan to add a feature, fix a bug, or refactor code; supports metacomm framing for design-intent briefs.

Build

  • /implement -- Execute a previously generated plan to add a feature, fix a bug, or refactor code.

Validate

  • /critique -- Critique quality: validation, code review, smoke tests, preflight, and harness health.

Share

  • /document -- Generate or update project documentation based on plan Docs: fields, auto-detection, or explicit type selection.
  • /communicate -- Generate tailored communication material for a specific audience segment.

Reflect

  • /reflect -- Run on-demand reflection anchored on specific plans, research reports, or other artifacts, recording your words verbatim.

Cross-Cutting / Supporting

These skills support the lifecycle from the side. They can be run at any point rather than at a fixed phase.

  • /pending -- List and address outstanding human actions from the pending ledger: verify implementations, flip status markers, run periodic curation, manage deferred work.
  • /qa-log -- Log the entire current Q&A session into a file for future reference; output goes to _output/qa-logs/.
  • /onboard -- Generate a tailored onboarding plan for a new team member based on their role and expertise level.
  • /publish -- Publish a tagged release to the public SEJA repository via the automated publish pipeline.
  • /seja-setup -- Manage the SEJA harness in this project: install, finalise an in-place download, create a workspace, bootstrap a demo, or upgrade harness files.
  • /help -- Show contextual help, browse skills by category, or get details on a specific skill.
