How to Communicate to an Audience

Goal: present the project to a specific audience in their language, focused on what matters to them. The /communicate skill generates tailored communication material for one of four audience segments: evaluators, clients, end users, and academics.

When to Use

  • You need to present the project to evaluators, clients, end users, or academics.
  • You want material that speaks each audience's language rather than a single generic summary.
  • You want to reformat an existing report (for example an advisory log) for a particular audience.

Not for new team-member onboarding (use /onboard) or project documentation (use /document).

Required Inputs

  • An audience segment or alias: evaluators / EVL, clients / CLT, end-users / USR, or academics / ACD. Or --all for every segment.
  • A project with design vision and design files the skill can read.
  • Optionally a source artifact to reformat, e.g. --source _output/research-logs/research-000100.md.

Step by Step

  1. Pick the audience.
    AudienceAliasesFocus
    Evaluatorsevaluator, EVLTechnical depth, architecture decisions, quality evidence
    Clientsclient, CLTValue proposition, ROI, project outcomes
    End Usersend-user, USRFeatures, benefits, how-to guidance
    Academicsacademic, ACDResearch context, methodology, theoretical framing
  2. Choose format and depth. By default the skill generates both Markdown and HTML. Use --format md or --format html to restrict output, and --deep to include expanded Deep-dive sections.
    • Single audience -- Recommended when you are presenting to one group. NOT recommended when you need parallel material for several groups at once.
    • --all -- Recommended when you want material for all four segments in one run, each generated in its own subagent.
  3. Run the skill. Output artifacts carry the communication-NNN prefix and land in _output/communication/.
    Expected output: audience-tailored material in the requested formats.

Tip. Per-audience tone, sections, and content strategy are defined in the communication reference files under .claude/references/general/communication/. Edit those files to change how each audience is addressed.

Expected Outputs

  • One or more communication-<id>-* artifacts in _output/communication/.
  • Markdown and/or HTML per the --format setting, with Deep-dive sections when --deep is passed.

Common Mistakes

MistakeBetter approach
Using /communicate to onboard a new hire. Onboarding is /onboard; it produces a personalized learning plan, not audience messaging.
Using /communicate to write project docs. Project documentation is /document. /communicate is stakeholder messaging.
Sending clients evaluator-grade technical depth. Pick the audience that matches your reader; each segment is tuned to a different focus.
Communicating before validating. Validate first with /critique -- the lifecycle rule is "validate before you communicate".
