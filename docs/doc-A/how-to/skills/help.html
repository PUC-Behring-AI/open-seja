How to Get Help and Browse Skills

Goal: find out what the harness can do, read the details of a specific skill before you run it, or browse the full catalogue interactively and launch a skill from a menu. The /help skill provides three layers of progressive disclosure so you can go as shallow or as deep as you need. It explains and navigates; it does not do the work itself.

When to Use

  • You want an overview of every user-facing skill grouped by workflow category.
  • You need the details of one skill -- its guide, arguments, category, and related skills -- before invoking it.
  • You want to browse the catalogue by category and launch a skill from an interactive menu (--browse).
  • You want to see how the skills relate to each other as a visual graph.

Not for execution. Once you know which skill to run, invoke it directly. /help stops after explaining.

Required Inputs

The argument pattern is [skill-name | --browse].

Argument Purpose
(none) Layer 1 overview -- all user-facing skills grouped by workflow category, each with a one-sentence summary.
[skill-name] Layer 2 detail card for one skill (Quick Guide, arguments, category, related skills).
--browse Layer 3 interactive category browser with a Mermaid skill-relationship graph; lets you pick a category, then a skill to run.

Step by Step

  1. Start with the overview. Run /help with no arguments. It lists all user-facing skills grouped into workflow categories (Getting started, Design & plan, Understand the system, Quality & review, Communicate, Housekeeping) with one-sentence summaries.
    Expected output: a categorised catalogue and a prompt asking which skill or category you want to explore.
  2. Drill into a specific skill. Run /help <skill> (e.g. /help research). The skill loads that skill's Quick Guide (What / Example / When to use / Next step), its Arguments table, its category, and its related skills from the skill graph.
    • Read the Quick Guide first -- Recommended when you are deciding whether a skill fits your task.
    • Jump to the Arguments table -- Recommended when you already know the skill and just need the flag surface.

    Expected output: a detail card ending with an invitation to run the skill.
  3. Browse interactively. Run /help --browse. The skill scans .claude/skills/ for every SKILL.md (excluding the internal pre-skill and post-skill hooks), groups them by metadata.category, shows category counts, renders a Mermaid skill-relationship diagram, and walks you through picking a category, then a skill, then executing it.
    Expected output: a category menu, a relationship graph, and a launch prompt for the chosen skill.

Tip. The relationship diagram is rendered from .claude/references/general/skill-map.mmd. To regenerate it, the harness runs python .claude/skills/help/generate_skill_map.py.

Expected Outputs

  • Layer 1: a categorised overview of every user-facing skill, plus drill-in options.
  • Layer 2: a per-skill detail card (Quick Guide, Arguments, category, related skills).
  • Layer 3: an interactive category browser with a Mermaid skill graph and a menu that launches the chosen skill.

/help writes nothing to _output/; it is a read-only navigation aid.

Common Mistakes

MistakeBetter approach
Expecting /help to perform the task. /help only explains and navigates. Invoke the target skill directly once you know its name.
Guessing a skill's flags instead of reading its card. Run /help <skill> to see the authoritative Arguments table before invoking.
Looking for internal hooks in the browser. pre-skill and post-skill are deliberately excluded from the menu; they are lifecycle hooks, not user-invocable skills.
Ignoring the "related skills" section. The skill graph shows the usual next step -- follow it to stay on the canonical lifecycle path.
