How to Log a Q&A Session

Goal: save the entire current conversation -- every question you asked and every answer the agent gave -- into a file for future reference. The /qa-log skill captures the full Q&A exchange, assigns a globally unique ID, and writes a timestamped Markdown file. You can provide a short title or let the skill derive one from the conversation topic.

When to Use

  • You have had a productive conversation with useful decisions or insights and want to preserve it as project documentation.
  • You want to capture a research exchange, design discussion, or debugging session before it scrolls out of view.
  • You are about to end a session and want an indexed record of what was covered.

Note. Post-skill also uses /qa-log internally to produce companion QA logs next to parent artifacts. You do not need to invoke it manually after a skill run -- post-skill handles that automatically.

Required Inputs

  • Nothing for a default invocation: /qa-log derives the title from the conversation topic.
  • Optionally, a short title: /qa-log Design decisions for the notification system.

Step by Step

  1. Decide whether to provide a title. If you pass one, it becomes the log file's title and slug. If you omit it, the skill derives a title from the conversation topic.
  2. Run the skill. Type /qa-log (with or without a title argument). The skill reserves a globally unique ID, captures all user prompts and agent responses in chronological order, and writes a timestamped Markdown file.
    Expected output: a file at _output/qa-logs/qa-<id>-<slug>.md with a numbered Q&A log.
  3. Check the output. The skill prints a link to the generated file and commits it automatically. The file includes a header with the ID, timestamp, and title, followed by numbered ## Q1 / ## A1 exchanges.

Tip. Lengthy agent responses (code generation, plan execution) are summarized in the log rather than reproduced verbatim. The log is a reference index, not a full transcript.

Expected Outputs

  • A qa-<id>-<slug>.md file in _output/qa-logs/.
  • Header with globally unique ID, timestamp (YYYY-MM-DD HH:MM UTC), and title.
  • Numbered Q&A exchanges: ## Q1, ## A1, ## Q2, etc.
  • An automatic commit with the message Log QA session: <title>.

Common Mistakes

MistakeBetter approach
Running /qa-log after every skill invocation. Post-skill already produces a companion QA log next to the parent artifact. Use /qa-log only for standalone sessions you want to preserve separately.
Expecting the log to be a full verbatim transcript. Long agent responses are summarized. The log is a reference index of what was discussed, not a raw dump.
Forgetting to provide a title for a multi-topic session. Pass a short title so the slug is descriptive. The auto-derived title works best for single-topic sessions.
