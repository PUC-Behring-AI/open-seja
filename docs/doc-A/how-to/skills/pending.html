How to Manage Pending Actions

Goal: see and resolve the outstanding human actions the harness is tracking for you. The /pending skill lists each action with type-specific advice, then stops. The ledger lives at _output/pending.jsonl and is append-only, so history is never lost. Six subcommands cover the full lifecycle: list, address, add, done, snooze, and dismiss.

When to Use

  • When pre-skill tells you there are pending actions at the top of a skill invocation.
  • After /implement, if you chose to defer follow-up work for later review.
  • When the periodic curation trigger has fired.
  • Any time you want to review what the harness is tracking for you.

Required Inputs

  • Nothing for a plain listing: /pending.
  • An item ID for a targeted subcommand, e.g. /pending address pa-000003 or /pending done pa-000003.
  • For add, a type, source, and description; for snooze, an --until date; for dismiss, a --reason.

What the Ledger Tracks

The harness files a range of action types, each with a typical resolution. Common ones include:

TypeFiled byTypical resolution
mark-implementedpost-skillFlip STATUS markers via /pending address
test-implementationpost-skillRun the plan's test plan manually
verify-as-codedpost-skillRun /explain drift to confirm
update-documentationpost-skill / --skip-docsRun /document --plan <source>

incorporate-research-markerspost-skillFlip INCORPORATED markers in UX research

periodic-curationperiodic triggerReview the ledger: dismiss stale items, snooze blocked ones, close the curation entry

create-decision-entry/research (decision-extract)Create a D-NNN entry in as-intended

Step by Step

  1. List what is pending. Run /pending. Items are grouped by type, each with advice on how to resolve it and which skill or file to reach for.
    Expected output: a grouped listing plus a footer of available subcommands. The skill then stops -- it does not act on your behalf.
  2. Address a guided item. For marker-flip types (mark-implemented, incorporate-research-markers), run /pending address <id> to walk through per-candidate flips with confirmation. For other types, the command prints type-specific advice.
  3. Manage the ledger. Choose the action that fits:
    • done -- Recommended when the work is finished. Marks the item complete.
    • snooze --until <date> -- Recommended when the item is valid but not now. It resurfaces on that date.
    • dismiss --reason <text> -- Recommended when the item is no longer relevant. NOT recommended when the work still needs doing -- prefer snooze. The reason is recorded.
    • add -- Recommended when you want the harness to track a custom reminder that pre-skill surfaces until resolved.

Expected Outputs

  • A grouped listing of outstanding actions with per-type resolution advice.
  • An updated append-only ledger entry in _output/pending.jsonl after a mutation (never a rewrite of history).
  • For address on marker-flip types, confirmed marker changes applied via apply_marker.py.

Common Mistakes

MistakeBetter approach
Expecting /pending to resolve everything automatically. The listing stops after showing advice. You choose address, done, snooze, or dismiss.
Editing _output/pending.jsonl by hand. Mutate through /pending subcommands so the append-only history stays intact.
Dismissing an item that still needs doing. Use snooze to defer; reserve dismiss for items that are genuinely no longer relevant.
Trying to mutate the ledger from /critique. /critique health only reports the count. Mutations flow through /pending.
