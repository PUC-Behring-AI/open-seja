How to Publish a Release

Goal: cut a tagged release and push it to the public SEJA repository in one step. The /publish skill wraps the full release pipeline: preflight checks, tag creation, cloning the public repo, syncing harness files, running smoke tests, committing, pushing, and closing the pending PUBLISH: entry. It supports version inference from CHANGELOG.md or an explicit version argument.

Maintainer workflow. /publish is for harness maintainers cutting a public release. It is not part of the feature-development lifecycle and does not apply to consumer projects using the harness.

When to Use

  • You are ready to cut a public release of the harness.
  • You want a preview of the exact command sequence before a live run (use --dry-run).

Not for internal harness iteration (just commit normally), changelog authoring (edit seja-public/CHANGELOG.md directly), or harness upgrades in consumer projects (use /seja-setup --upgrade).

Required Inputs

  • An optional version, e.g. /publish v0.3.0. Omit it to infer the next version from CHANGELOG.md and git tags.
  • Prerequisites: seja-public/CHANGELOG.md has content under ## Unreleased, the working tree is clean, and the remote is reachable.

Step by Step

  1. Prepare the changelog and working tree. Ensure seja-public/CHANGELOG.md has content under ## Unreleased and commit any outstanding work so the tree is clean.
  2. Optionally run a quality gate. Run /critique preflight beforehand for a go / no-go verdict.
  3. Choose how to run.
    • Dry run (--dry-run) -- Recommended when you want to verify the pipeline before a live push. NOT recommended as the final step -- it executes nothing destructive.
    • Explicit version (/publish v0.3.0) -- Recommended when you know the exact version to cut.
    • Inferred version (/publish) -- Recommended when you want the skill to propose the next version from the changelog and tags, then confirm with you.
    • Non-interactive (--yes) -- Recommended for scripted releases where you accept all prompts. NOT recommended for a first release or when you want to review each step.
  4. Run the skill. It runs preflight, cuts the tag, clones the public repo, syncs harness files (stripping private content), runs smoke tests, commits, and pushes.
    Expected output: a tagged release pushed to the public repository and the pending PUBLISH: entry closed.

Expected Outputs

  • A new tag and a commit pushed to the public SEJA repository.
  • Private-only content stripped from the published copy by the sync pipeline.
  • The pending PUBLISH: ledger entry closed.

Common Mistakes

MistakeBetter approach
Publishing with a dirty working tree. Commit or stash first. The pipeline expects a clean tree.
Forgetting to fill ## Unreleased in the public changelog. Author seja-public/CHANGELOG.md before publishing; version inference reads it.
Using /publish to upgrade a consumer project. Consumer upgrades use /seja-setup --upgrade. /publish cuts the public release.
Skipping --dry-run on an unfamiliar release. Preview the pipeline first; --dry-run shows the exact sequence with no destructive action.
