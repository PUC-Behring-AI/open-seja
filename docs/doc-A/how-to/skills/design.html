How to Define Design Intent

Goal: establish or update your project's design intent -- stack, conventions, domain model, conceptual design, standards, and the metacommunication message. The /design skill owns design intent; /seja-setup owns topology scaffolding. After /seja-setup populates product-design/conventions.md with stack definitions, /design generates the remaining design-intent artifacts and amends CLAUDE.md.

When to Use

  • Right after /seja-setup, to define design intent for a new project.
  • Anytime you want to update design foundations -- domain model, standards, or the metacommunication message.
  • When you want to jump straight to one section with /design update <section-slug>.

Not for topology scaffolding (use /seja-setup), planning implementation (use /plan), or checking drift between intent and code (use /explain drift).

Required Inputs

  • A project where /seja-setup has already populated product-design/conventions.md (for the post-setup flow).
  • Optionally a pre-filled spec file for the non-interactive path, e.g. /design specs/my-project.md.
  • For a targeted update, a valid section slug: stack, conceptual, metacomm, backend-standards, frontend-standards, ux-standards, ui-standards, i18n, security, testing, constitution, or full.

Step by Step

  1. Choose a mode.
    • Interactive questionnaire (default) -- Recommended when you know your stack and want speed. NOT recommended when you have not yet formalized your idea.
    • Interview (--mode interview) -- Recommended when you want to think out loud and let the skill synthesize structured outputs. NOT recommended when you already have a spec ready to feed in.
    • From a spec file (/design <path>) -- Recommended when you have a pre-filled spec and want all artifacts generated without prompts.
    • Generate a blank spec (--generate-spec) -- Recommended when you want to fill out the spec offline first.
  2. Walk through the sections. In the default post-setup flow, the skill skips Section 1 (stack already answered) and walks through Section 0 (metacommunication) and Sections 2-5+ (conceptual design, UX / visual design, standards, docs).
    Expected output: the skill generates product-design/product-design-as-intended.md, product-design/ux-research-results.md, product-design/standards.md, product-design/design-standards.md, product-design/security-checklists.md, and product-design/constitution.md, and amends CLAUDE.md.
  3. Or target one section. Run /design update conceptual (or any valid slug) to jump directly to that section's update dialog, skipping the menu.
  4. Review the generated intent. Read the generated files end to end -- entity names, role labels, and the metacommunication message are hardest to change once plans are written against them.

Expected Outputs

  • A populated product-design/ directory with intent, UX research, standards, and constitution files.
  • An amended CLAUDE.md reflecting the project's design.
  • A first-person metacommunication message ("I want you to ... so you can ...") captured in product-design/product-design-as-intended.md.

Common Mistakes

MistakeBetter approach
Using /design to scaffold directories or detect the stack. Topology and stack detection belong to /seja-setup; /design owns design intent.
Editing the constitution as if it were agent-writable. product-design/constitution.md is Human-owned and never agent-altered. Edit it yourself.
Writing the metacommunication message in third person. Use the first-person "I / you" convention -- it is the designer speaking to the user through the system.
Jumping to /plan before reviewing generated intent. Read and adjust the design files first; corrections are cheap now and expensive after plans reference them.
