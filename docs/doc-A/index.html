SEJA Documentation

SEJA is an agent harness that makes Claude Code governable and epistemic. It structures every AI-assisted development session around a lifecycle of research, planning, implementation, critique, and reflection -- grounded in semiotic engineering, reflective practice, and abductive reasoning. This collection covers everything from first-time setup to the theoretical foundations that distinguish SEJA from every other agent harness.

This edition is written for every SEJA reader -- from first-time users to contributors, architects, and theorists. It is organized by the kind of help you need rather than by the harness's internals: its four volumes follow the Diataxis model -- Tutorials to learn by doing, How-To guides to accomplish a specific task, Reference to look a detail up, and Explanation to understand the why. The intent is to let you enter by what you are trying to do right now; the reading map below routes you to the matching volume.

What is your role?

Start here. Find the volume that matches your goal, then follow the chapter links within it.

New user -- "I want to get started"
Begin with Vol. 1: Tutorials. The five guided walkthroughs take you from zero to a working project in under an hour, building understanding through hands-on experience.
Experienced user -- "I need to accomplish a specific task"
Go to Vol. 2: How-To Guides. Goal-first guides cover installation variants, skill-by-skill workflows, governance operations, design maintenance, and customization.
Contributor or architect -- "I need to look something up"
Consult Vol. 3: Reference. Exhaustive tables and specifications for every skill, subagent, script, reference file, pipeline stage, file format, and configuration variable.
Academic or theorist -- "I want to understand the why"
Read Vol. 4: Explanation. Narrative prose exploring the semiotic engineering foundation, reflective practice, the dual design thesis, and the design decisions behind SEJA.
AI agent -- "I process this harness programmatically"
Agent-facing documentation lives in .claude/ (SKILL.md files, references, rules). This human-readable collection is not optimized for agent consumption. See Vol. 4 Ch. 5: How the Agent Reads SEJA for how Claude processes the harness.

How Not to Use SEJA

Knowing the common ways SEJA is misused is as valuable as knowing how to use it well. How Not to Use SEJA catalogs seven anti-patterns -- each with its symptom, its consequence, and the correct approach -- that undermine SEJA's governance and epistemic guarantees. Read it once you are comfortable with the lifecycle.

  • Bypassing the lifecycle -- skipping research, planning, or critique.
  • Hand-editing Human (markers) files -- editing marker-managed files by hand instead of via the marker tooling.
  • Skipping pre-commit hooks -- bypassing preflight and the private-leak gate with --no-verify.
  • Mixing private content into public docs -- letting priv-only material reach the public collection.
  • Ignoring pending actions -- leaving the /pending ledger unattended.
  • Treating the constitution as optional -- overriding non-negotiable rules without a decision record.
  • Running /implement without a plan -- coding before a plan exists in _output/plans/.
